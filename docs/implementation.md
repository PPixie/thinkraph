## 验证证据（2026-09-17）

`npm run typecheck`、`npm run build` 通过。40 项自动测试通过：15 项既有 DAG 与汇总规则、5 项模型协议、4 项保存队列、16 项文件仓库／API／导入恢复测试。

文件故障覆盖临时文件同步后、正文重命名后、索引更新失败、空间准备阶段失败、指针切换后回执失败，以及单图回执失败。验证了正文完整性、失败不暴露部分空间、重启恢复回执、重复提交不重复创建、未知版本不被覆盖、损坏文件可从备份显式恢复。

保存队列验证了单图只有一个在途请求、旧响应不会覆盖新编辑、响应丢失后的重试沿用 mutationId、冲突保留本地草稿，以及 React Flow 展示属性不触发正文保存。额外回归用例确认仅更新画布视图不会重置主题、标题折叠或面板宽度。

浏览器在独立测试目录 `/tmp/thinkraph-browser-qa-20260917` 验证：

- 加载示例、添加笔记、保存后刷新；资料手工录入写入图谱 JSON；RAG 测验作答后，选项、结果与时间保存到 attempts。

## 验证范围与已知边界

模型协议采用模拟上游测试 UTF-8 分块流、结束事件、中断、错误 JSON、循环依赖草稿与未配置提示。未发起真实供应商请求，因此不宣称已验证具体供应商的联网可用性或生成质量。模型配置保存在本地 `data/config.json`，旧 `.env` 仅作为兼容回退；平台 API 和导出文件均不返回密钥原文。

生产构建有前端包体积提示（加入 Markdown、数学与高亮后，主包约 1,864 kB，gzip 约 563 kB；高亮语言按需加载），不影响本地启动。未进行完整屏幕阅读器专项验收。数据目录故障中无法自动恢复的空间指针或锁文件会明确报错并保留文件，需要按 README 操作；应用不静默替换为空空间。

实现采用原生 React 外部 store 和共享类型，未引入额外状态库。文件 API、导入用例和存储职责集中在 server/app.ts 与 server/storage/repository.ts，前端工作台继续逐步拆分；职责对应架构方案，不为目录层级额外拆空模块。

## 学习助手 Markdown 更新（2026-09-17）

新增 `MarkdownContent`、`AssistantMessage` 与 `conversationMessages`，使用 Streamdown 及 code / cjk / math 插件。流式草稿和已保存消息使用同一 ID、容器与解析模式，避免落盘期间的重复消息，以及停止时未闭合格式退回纯文本。通过 `data-streamdown` 属性和独立的 `src/markdown.css` 适配现有主题，不引入 Tailwind。笔记总览与节点笔记也渲染 Markdown；服务端提示词要求合理使用 Markdown，存储格式不变。

45 项测试、类型检查与生产构建通过。新增测试覆盖语义格式、未闭合代码/加粗、生成前后结构一致、HTML 清理与危险链接、消息去重及节点隔离。隔离目录 `/tmp/thinkraph-markdown-qa-data` 中的模拟 SSE 浏览器验证覆盖完成、停止、中断重试、代码复制、保存笔记，以及浅色、深色与 390×844 窄屏。实测生成前后正文均为 13 px / 24.05 px 行高，DOM 消息身份保持不变，保存过程中仅一份回复；窄屏页面和助手滚动宽度均未超出可见宽度。没有调用真实模型或改动用户学习数据。
